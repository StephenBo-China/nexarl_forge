# Windows 原生运行设计

## 目标与约束

在同一仓库中增加 Windows 原生运行能力。用户安装 Windows Python 3.10+ 和 Git 后，可以通过 PowerShell 或 Git Bash 安装、启动和管理 Nexarl Forge；运行链路不调用 WSL、Linux Python、systemd 或 macOS LaunchAgent。复用现有管理页面、记忆审批、项目注册、Codex/Claude Code hook、设计管理和 Git worktree 能力，不另写缩水版业务实现。

不在本轮实现免 Python 安装包、Windows 系统服务或 WSL 个人记忆的自动搬迁。WSL 数据若要迁移，应另行明确源目录和目标目录，避免覆盖已有正式记忆。

## 方案选择

用户已选择同仓库适配。对比独立 Windows 分支，此方案能够共享业务逻辑和修复，代价是需要明确划分平台接口并增加跨平台回归测试。保留现有 macOS 实现，Windows 使用独立的平台实现，不通过伪造 POSIX API 或全局 monkey patch 绕过安全检查。

以下具体实现由开发者确定，作为本设计的建议默认值。

## 平台边界

1. 增加平台工具模块，提供文件锁、安全文件读写、路径检查和命令参数生成。Windows 使用标准库 `msvcrt` 或 Windows 原生 API；POSIX 保留现有行为。
2. Windows 无法使用目录文件描述符与 `dir_fd`，相关路径采用 Windows 实现；检查符号链接、junction 和重解析点，拒绝通过不受信任的链接操作记忆或安装目录。写入使用同目录临时文件与原子替换，保留并发锁与冲突检测。
3. Windows 权限采用当前用户目录继承的 ACL，敏感目录限制到当前用户及必要系统主体；不把 `chmod(0600)` 当作有效的 Windows 隔离机制。实现可使用系统自带工具，不能新增必须手工安装的依赖。
4. Unicode、中文、空格路径是支持范围。Python 子进程使用参数数组，Windows hook 使用明确的解释器和脚本绝对路径，避免依赖 Unix 环境变量前缀与 shell 替换语法。

## 路径与数据

- 安装位置默认 `%LOCALAPPDATA%\NexarlForge`；安装后的运行时使用独立副本，不依赖源码 checkout 的位置。
- 个人记忆继续位于 Windows 用户目录下的 `.codex\personal_memory`；注册表及设置放在用户目录下的 `.codex` 中。
- 项目记忆保存在已注册项目自己的 `codex` 目录。未注册目录的 hook 不产生项目记忆文件。
- 不自动读取或写入 WSL 用户目录，不更改已有个人正式记忆；初始化仅创建缺失文件。
- 保留既有记忆数据结构和审批要求，候选不会自动升级为正式记忆。

## 安装与命令

提供 `install.cmd`，由 Windows Python 执行 Windows 安装流程；`install.sh` 在 Git Bash 环境转交相同流程。安装器验证 Python/Git，复制运行文件，生成启动命令，按既有规则合并用户 hook 并保存备份，启动本地服务并执行 doctor。

提供 Windows 的 `nexarl-forge.cmd` 与 Git Bash 可调用入口，至少覆盖 install、start、stop、restart、status、doctor、open、hook、项目与记忆操作，以及与管理页面关联的生命周期接口。通过绝对路径也能使用命令，不把全局 PATH 修改作为启动前提。

安装、修复和卸载只处理工具拥有的文件、hook 与自启项；保留其他 hook 和用户记忆。首次设置与管理页面的平台文案应能正确反映 Windows。

## 后台与登录自启

后台使用 Windows Python 原生独立进程，绑定 `127.0.0.1`，保留现有端口配置（默认 8897）和健康检查。start 等待服务就绪，重复启动不创建多个后台；端口被其他程序占用时报告冲突。

停止必须验证进程属于本工具，并防止 PID 重用导致误杀；优先使用受验证的本地控制路径或带身份校验的进程句柄。后台输出写到用户运行目录日志中。

登录自启采用当前用户的启动文件夹，无需管理员权限；安装和运行均不依赖 PowerShell、不注册计划任务、不安装 Windows 服务；默认遵循已有 first-run 设置。临时 start 不改变登录自启偏好。卸载移除本工具自启项并停止后台，但不删除记忆与项目文件。

## hook 与现有业务

Codex 和 Claude Code 的全局 hook 均直接调用安装时选定的 Windows Python，不经过 WSL。保持事件归一化、fail-open、超时、上下文注入和候选审批治理。hook 不能直接复制用户原文作为候选，也不能调用另一个模型自动总结。

Windows 项目初始化生成可执行的原生 hook 和候选提交示例。注册表、队列、迁移、设置、设计存储的锁与原子写入均走受测的平台接口。Git worktree 使用已安装的 Windows Git，针对遇到的 shell 专属调用逐项适配。

## 验证与验收

在 Windows Python 下执行针对性单元测试和端到端测试。所有测试使用临时用户目录、临时注册项目与可用端口，不改当前用户真实的 hook、记忆或登录自启项。

验收至少覆盖：

- 中文和空格路径安装、再次安装、独立运行副本、卸载后记忆保留。
- start / status / health / stop / restart；重复启动与端口冲突。
- 登录自启配置生成和移除（使用隔离配置或模拟系统接口，避免修改本机真实偏好）。
- Codex / Claude Code hook 合并、执行、上下文读取，保留第三方 hook。
- 已注册项目内的候选创建、列表与明确审批；未注册目录不写项目数据。
- 多进程锁互斥、原子写入、符号链接或 junction 拒绝策略。
- Windows 下实际可执行的 CLI 与管理页面主要 API。
- 保留原平台实现的回归检查；本机无法执行的 macOS 专用测试明确列为未验证，不宣称通过。

主要中文安装文档以 UTF-8 保存，并检查乱码替换字符与页面文字。

## 风险与实施余地

当前安装器大量依赖 macOS 安全文件 API，不能只把 `fcntl` 换掉即宣称原生支持。需要逐项验证调用链。跨平台接口的函数拆分、Windows 后台身份验证方式、运行副本版本管理形式及自启机制具体载体留给实施者选择，但必须满足上述隔离、并发、无管理员依赖和卸载保留数据的约束。
