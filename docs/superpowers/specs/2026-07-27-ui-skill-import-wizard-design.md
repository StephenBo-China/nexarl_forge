# UI Skill 三步导入向导设计规格

## 背景与目标

当前 `UI Skills` 网页只提供“从编辑器导入”，尽管后端已经支持编辑器、本地目录、本地 ZIP 和固定 GitHub revision。新增三步向导，使四种来源在网页中可发现、可配置、可复核，同时保持“导入不等于批准，批准不等于发布”的安全边界。

## 已确认决策

- 使用三步向导，不使用标签页或单表单。
- 本地目录与 ZIP 使用本机绝对路径输入，不增加浏览器上传。
- 四种来源：编辑器、本地目录、ZIP、GitHub。
- 用户可以选择全局或当前项目作用域、版本标签、Codex 与 Claude Code 目标；发布目标至少选择一个，默认双端。
- 第三步只创建草稿并执行静态校验，不自动批准、发布或执行包内脚本。

## 信息架构

向导从 `UI Skills` 工具栏的“导入 UI Skill”打开：

1. **选择来源**：四张来源卡片说明各自输入方式。
2. **配置导入**：显示来源专用字段，以及共享的作用域、版本标签和发布目标。
3. **确认并校验**：显示只读摘要、安全提示和“导入并静态校验”动作。

成功后向导关闭，列表刷新并把新草稿置于可见位置。校验报告、批准、发布、退回、拒绝、回滚和停用仍在受管 Skill 卡片中完成。

## 来源字段

- 编辑器：完整 `SKILL.md`。
- 本地目录：包含 `SKILL.md` 的本机绝对目录路径。
- ZIP：本机 ZIP 文件绝对路径。
- GitHub：`owner/repository`、仓库内 Skill 路径、40 位完整 revision。

服务端仍是路径存在性、包大小、许可证、网络引用、路径安全和脚本风险的权威校验层。

## 交互与状态

- 步骤 1 未选择来源时禁用继续；改变来源会清除来源专用字段，但保留共享字段。
- 步骤 2 在离开字段或继续时校验；错误包含原因和修复方法，并聚焦第一个错误字段。
- 步骤 3 完整显示本地路径与 revision；编辑器内容只显示字符数和首行摘要。
- 提交时禁用重复动作，显示“正在导入并校验…”，使用 live region 宣布进度。
- 成功消息包含 Skill 名称、草稿 ID、摘要和下一步。
- 服务端失败时保留全部输入，提供重试和返回修改；幂等键避免重复草稿。
- 有未提交内容时取消或 Escape 需要确认。

## 视觉与可访问性

延续审核台现有深色、紧凑、工具型视觉。步骤条表达真实安全流水线，不增加渐变、发光、装饰图标或阻塞动画。

- 当前步骤高对比，其他步骤使用低强调边框。
- 来源选择、错误、成功和焦点不只依赖颜色。
- 使用持久标签、帮助文本、单选组/复选框语义、`aria-current="step"`、`aria-describedby` 和 live region。
- 触控目标至少 44×44 CSS 像素，正文对比符合 WCAG 2.2 AA。
- 动效仅限 150–200ms 色彩/边框过渡，并支持 reduced motion。

## 响应式

- ≥1024px：约 720px 居中面板，来源卡片两列。
- 768–1023px：面板占可用宽度，来源两列、字段单列。
- 375–767px：来源和字段单列，步骤标题压缩，动作纵向排列，页面可随软键盘滚动。
- 验收视口：375×812、768×1024、1024×768、1440×900。

## 实现范围

- `scripts/memory_review_server.py`：向导结构、样式、客户端状态与现有导入 API 参数组装。
- `tests/test_ui_design_server.py`：页面结构、字段规则、四种来源请求、错误和状态测试。
- `docs/MEMORY_REVIEW_USER_GUIDE.zh-CN.md`：网页导入步骤说明。

不修改 Skill 注册、校验、发布、门禁 Hook 或记忆审批逻辑。

## 验证标准

- 四种来源都可通过网页生成正确的 `/api/ui-skills/import` 请求。
- 单端和双端目标、全局和项目作用域参数正确。
- 不完整 GitHub revision、相对路径、空编辑器和零发布目标在提交前给出可恢复错误。
- 服务端错误保留输入并支持幂等重试。
- 自动化测试通过，并用浏览器完成桌面、移动端、键盘和 reduced-motion 验收。
