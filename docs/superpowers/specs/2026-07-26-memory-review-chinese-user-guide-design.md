# 记忆审核台中文版使用说明书设计规范

## 目标

在 `docs/MEMORY_REVIEW_USER_GUIDE.zh-CN.md` 新增一份可独立阅读的完整中文说明书，并在根目录 `README.md` 增加入口。说明书面向首次使用者、日常操作者和需要排障的维护者，覆盖记忆审核、项目管理、Loop Engineering、UI 设计审批与 UI Skill 管理的完整工作流。

## 文档形态

- 使用单一 Markdown 文件，便于搜索、离线阅读、版本审查和随仓库分发。
- 采用“快速开始 → 日常操作 → 高级能力 → 运维排障 → 安全边界”的阅读顺序。
- 所有命令使用仓库内现有 CLI 和服务入口，不引入不存在的脚本或第三方依赖。
- 命令中的项目路径、任务 ID、摘要和幂等键均使用明确占位符，避免误复制真实凭据或本机敏感信息。

## 章节结构

1. 产品定位与核心概念
2. 目录、数据和权限模型
3. 安装要求与首次启动
4. 项目注册、切换、初始化和状态检查
5. 记忆候选的产生、审核、批准、驳回、延期和隔离
6. 个人记忆与项目记忆的适用范围
7. Web 控制台各页面说明
8. CLI 常用命令与完整操作示例
9. Loop Engineering 初始化、升级和发布边界
10. UI 设计偏好：全局值、项目覆盖与有效上下文
11. UI Skills：导入、校验、审批、发布、扫描、回滚和停用
12. 设计包生命周期与 `design_package` 门禁模式
13. `project_global` 门禁模式、重新锁定和模式切换
14. Codex/Claude Hooks、客户端重启与 smoke test
15. 备份、恢复、审计、幂等冲突和摘要冲突
16. 常见问题与故障排查
17. 主分支、远程 staging 和生产部署安全边界
18. 日常使用检查清单

## 信息来源与准确性

说明书只以当前功能分支中的 `README.md`、CLI `--help`、模板、测试和实现代码为依据。涉及默认端口、文件路径、门禁模式、确认参数、幂等键及恢复操作时，必须与实现逐项核对。无法由代码确认的行为不得写成既定事实。

## 示例策略

- 快速开始使用中心仓库路径和 `<目标项目路径>` 占位符。
- UI Skill 示例覆盖内置 bootstrap、固定 Git revision、审批摘要和双目标发布。
- 设计包示例提供完整 manifest，并展示未批准、批准、越界和失效四种结果。
- 故障排查按“症状 → 检查命令 → 原因 → 安全处理”组织。
- 不出现 token、验证码、API Key、数据库密码、云存储密钥或真实生产参数。

## 安全边界

- 明确区分“批准记忆”“批准 UI Skill”“批准设计包”“合并主分支”“部署生产”，这些权限互不替代。
- 明确 UI hard gate 默认关闭，只有正式路径、设计产物路径和两端 Hook smoke test 均通过后才能启用。
- 明确纯后端和无界面任务不触发 UI 设计门禁。
- 明确导入的 Skill 脚本只做静态清点，不在审批或发布时执行。
- 明确不得用删除、强制覆盖或绕过摘要检查处理冲突。

## 验收标准

- 文档为完整中文，首次使用者可仅依赖该文档启动服务并初始化项目。
- Web、CLI、记忆、Loop、UI Skills、设计偏好、两种门禁模式和恢复流程均有独立章节。
- 所有示例命令对应当前 CLI，危险操作标明确认边界。
- README 能直接链接到说明书。
- 文档不存在 `TODO`、`TBD`、未解释占位符、真实凭据或与实现矛盾的说明。
- 修改后运行完整自动化测试、Markdown/链接人工复核和 `git diff --check`。

## 非目标

- 不重写现有英文 README。
- 不改变服务、API、CLI 或 UI 行为。
- 不在本次说明书任务中增加截图、视频或在线托管站点。
- 不执行远程推送、staging 部署或生产部署。
